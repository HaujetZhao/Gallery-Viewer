## Phase 1:文件资源池 ✅

- **日期**:2026-07-28
- **提交**:`b8aad05`(实现) + `87e620f`(code review 小修)
- **状态**:代码完成 + 审查通过,**待用户浏览器验收**

### 目标
把 SmartFile 的 `blobUrl`/`file`/`_size`/`_lastModified` 四个字段从实例抽到独立资源池 `fileResource`,集中 URL 生命周期(杀 blobUrl 泄漏类 bug),并为 Phase 2 纯列表 scan 解锁(scan 构造 SmartFile 不再被迫 getFile)。**本轮 scan 仍急切 getFile(行为等价),只是结果灌进池而非字段。**

### 核心设计:owner-based 门面
- 新建 [fileResource.js](../../../src/services/fileResource.js):`Map<SmartFile, entry>` 引用计数池,API `acquire/release/destroy/peek`。
- SmartFile 当池门面:`blobUrl`/`size`/`lastModified` 从字段改 getter(读池或 `_meta` 快照槽),`ensureBlobUrl`=acquire、`dispose`=destroy;新增 `_meta={size,lastModified}` 快照槽(fromSnapshot 填,repeat-open 零 IO 依赖);保留 `md5`。
- **收益**:消费方读 `file.blobUrl`/`file.size` 语法不变(字段读==getter 读),8 个消费方零改动——diff 比文档字面"改 6 消费方"小得多。

## Phase 2:纯列表 scan + 后台并发补全 ✅

- **日期**:2026-07-28
- **状态**:代码完成,**待审查 + 待用户浏览器验收**

### 目标
把 `SmartFolder.scan` 拆成「`scan` = 纯列名差集(零 getFile,瞬间出列表)」+「`enrich` = 后台并发 getFile 补 size/mtime」。大文件夹首开"瞬间出列表"(名字 + 排序),enrich 在后台并发补全后,Vue 响应式触发 sort 重排。**sort-by-size/date 在 enrich 前的 UX = 瞬时出 + 补全后重排**(缺省项兜底排末尾,无 loading 态,列表可能轻微跳序);name 排序(默认)零依赖不受影响。

### 核心设计
- **scan() = 纯列名差集(零 getFile)**:保留为实例方法(Phase 3 才纯函数化)。
  - values() 列名 + 差集(名字集合比对)+ 信任短路(名字集合一致 → 零 IO 沿用缓存)。
  - 新建文件 `new SmartFile({ handle, parent })`——**不 acquire、不 getFile、_meta=null、md5=null**。
  - **删除非 trust 校验路径**(原 ⑤ 里 size/mtime 校验 + 就地刷新):Phase 2 简化为纯名字集合。文档 §2.3:名字集合是最优信号,原地同名替换罕见,reload 兜底抓增删改名即可。
  - 零 getFile → 秒出。
- **enrich({ token }) 实例方法(新)**:补 `this.files` 里"待补"的文件。
  - targets = `this.files.filter(f => peek(f) == null && f._meta == null)`(listFolder 新建的、池空且无快照的)。信任短路后既有文件(_meta 有)→ targets 空 → 信任路零 getFile。
  - `await runConcurrent(targets, async f => { const file = await f.handle.getFile(); await acquire(f, f, file); f._meta = { size, lastModified }; }, { concurrency: SCAN_CONCURRENCY, token })`。
  - **acquire 灌池(url/file)+ 写 _meta 触发 Vue 响应式**(关键)。
- **size/lastModified getter `_meta` 优先**(响应式陷阱,类比 be2ffe3):`_meta` 是 SmartFile 实例字段(在 store 的 reactive files 数组里,属性变更触发 Vue 响应式);peek 读普通 Map(不响应式)。enrich 写 _meta → Gallery sort computed 重排。若仍优先 peek,enrich 后 size 变了 Vue 不知道,sort 不重排。`?? peek` 兜底(_meta 漏写时)。
- **所有 getFile 处补 _meta**(响应式一致性):除 listFolder(故意不写,_meta=null 是"size 暂缺"来源),其他 getFile 处写 _meta——operations.js `FileDeleteOperation.undo`、SmartFile.rename(move 后读 entry.file 写 _meta)。
- **Gallery sort NaN 兜底**:enrich 前 size/lastModified undefined → NaN 排序乱。兜底 `(a.size ?? Infinity) - (b.size ?? Infinity) * dir`(undefined 排末尾)。enrich 写 _meta 后响应式重排。
- **消费方 ensureBlobUrl 连锁**:listFolder 零 getFile → 新文件 peek 空 → blobUrl null。读 blobUrl 的消费方在 enrich 前调会拿到 null,加 ensureBlobUrl(懒 acquire,复用 enrich 的池,不重复 IO):
  - thumbnail.js `generateThumbnail` 开头 `await file.ensureBlobUrl()`;md5 计算复用 `peek(file)?.file`(省一次 getFile)。
  - MediaModal.vue watch currentFile:**所有类型**先 ensureBlobUrl(image/video 直接读 blobUrl,audio/svg 靠 ensureBlobUrl 后 peek 有 url)。
  - metadata.js 4 strategy getMetadata 开头各加 `await file.ensureBlobUrl()`(属性面板晚调,边界保险)。
  - useModal.js `copyCurrent`(Ctrl+C 复制)复用 `peek(file)?.file`(Modal 已 ensureBlobUrl)。
  - **PhotoCard onDragstart 不动**(同步不能 await,注释已说"blobUrl 可能 null,外部 MIME 跳过",enrich 后正常)。

### 行为变化(用户验收用)
1. **scan 不再同步 getFile**:大文件夹首开"瞬间出列表"(name 排序零依赖,体验最佳);sort-by-size/date 在 enrich 前缺省项排末尾,enrich 完成后(通常秒级)响应式自动重排,可能轻微跳序,无 loading 态。
2. **reload 不再 size/mtime 校验**:Phase 2 简化为纯名字集合 + enrich 新增项。原地同名同尺寸替换(罕见)检测不到,文档 §2.3 接受(reload 兜底抓增删改名)。
3. **新文件 blobUrl 懒**:enrich 完成 blobUrl 前 null,消费方(thumbnail/MediaModal/metadata)ensureBlobUrl 懒建(复用 enrich 池,不重复 IO);PhotoCard onDragstart 同步不能 await,enrich 后正常拖拽。

### 用户验收点
- 大文件夹(>200 文件)首开瞬出列表(name 排序),size/date 排序瞬出后 enrich 重排(轻微跳序)。
- 缩略图(图/视频/音频/GIF/SVG)、弹窗(Modal 全类型)、音频播放、拖拽到外部、Ctrl+C 复制、重命名、删除+撤销(`.trash`)、多文件夹切换、属性面板 size/日期。
- 边界:enrich 完成前打开 Modal / 属性面板 / 缩略图 → ensureBlobUrl 懒建兜底,不出现图裂/null size。
