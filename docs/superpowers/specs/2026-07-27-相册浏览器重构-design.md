## 1. 背景与目标

把原生 JS 版相册浏览器重构为 Vue 3 + Vite 工程，要求：

1. **两个 build**：
   - `npm run build` → 单个 `dist/index.html`（所有资源含字体 base64 内联，可 `file://` 双击离线运行）
   - `npm run build:pwa` → PWA 应用（SW 预缓存 + manifest，可安装、可离线）
2. **资源全内化离线，零 CDN**：Font Awesome、SparkMD5、exif-js 等都装 npm 包通过 ES import 引入，Vite 自动内化。
3. **迁移策略**：按源码 `<script>` 加载顺序自底向上逐模块迁移，最后联调。
4. 功能与体验**对齐源工程**（不增不减），UI 体验由用户上手验收。

## 2. 技术栈决策

| 维度 | 决策 | 理由 |
|---|---|---|
| 框架 | Vue 3（`<script setup>`） | 用户指定 |
| 构建 | Vite 5 | 用户指定，与参考模板一致 |
| 语言 | 纯 JavaScript | 与参考模板一致，对 17000 行迁移最友好 |
| 状态管理 | Pinia | 跨组件应用状态（currentFolder/foldersData/visibleFileList/主题/撤销栈/toast）集中管理 |
| 样式 | 原样搬源码 11 个 CSS，全局 import | 保留 60+ 变量设计系统 + 3 套主题的 `:root` 变量机制，迁移成本最低 |
| 路由 | 无 | 单页应用，启动页/主界面靠响应式状态切换 |
| 测试框架 | 暂不加 | 源码与参考模板均无；靠 `npm run dev` + 用户上手验收；复杂纯逻辑留最小 `assert` 自检 |
| 双 build 区分 | 两个独立 config 文件 + `--config` 切换 | 照搬 SubTap：SW/manifest 必须外链，无法内联进单 HTML，参数化会污染主配置 |

## 3. 双 build 配置

### 3.1 单 HTML build — `vite.config.js`

```js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { viteSingleFile } from 'vite-plugin-singlefile';

export default defineConfig({
  plugins: [vue(), viteSingleFile()],
  base: './',
});
```

`viteSingleFile()` 会把所有 JS/CSS/字体（含 font-awesome woff2）base64 内联进单个 `dist/index.html`。

### 3.2 PWA build — `vite.config.pwa.js`

```js
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    vue(),
    VitePWA({
      registerType: 'autoUpdate',
      manifest: {
        name: '相册浏览器',
        short_name: '相册',
        description: '纯本地处理的相册浏览器：文件树、瀑布流、EXIF、文件整理。',
        theme_color: '#2d3e50',
        background_color: '#2d3e50',
        display: 'standalone',
        start_url: './',
        icons: [
          { src: 'icon-192.png', sizes: '192x192', type: 'image/png', purpose: 'any maskable' },
          { src: 'icon-512.png', sizes: '512x512', type: 'image/png', purpose: 'any maskable' },
        ],
      },
      workbox: {
        // 补 woff2:源模板的 globPatterns 漏了字体,严格离线需加上
        globPatterns: ['**/*.{js,css,html,svg,png,json,wasm,woff2}'],
      },
    }),
  ],
  base: './',
});
```

## 4. 资源内化方案

| 资源 | 源（CDN） | 目标（内化） |
|---|---|---|
| Font Awesome 6.4.0 | `cdnjs.cloudflare.com/.../all.min.css` | `@fortawesome/fontawesome-free` npm 包，`main.js` 里 `import '@fortawesome/fontawesome-free/css/all.min.css'` |
| SparkMD5 3.0.2 | `cdnjs.../spark-md5.min.js` | `spark-md5` npm 包，`import SparkMD5 from 'spark-md5'` |
| exif-js | `cdn.jsdelivr.net/npm/exif-js` | `exif-js` npm 包，`import EXIF from 'exif-js'` |
| favicon | inline SVG data URI | 同样 inline SVG data URI（不外链文件，保单 HTML 完整） |
| PWA 图标 | 源码仅 `dist/icon.svg` | 从 `D:\repos\相册浏览器\dist\icon.svg` 渲染生成 192/512 PNG，放 `public/`（占位，用户可替换） |
| 源码 CSS（11 个） | `css/*.css` | 搬到 `src/styles/`，`main.js` 全局 import |

**font-awesome 图标子集**：源码用到 `fas`/`far`/`fab` 三种前缀、约 50+ 图标（见源码报告）。用 `all.min.css` 全量引入（简单可靠），Vite + singlefile 会把用到的 woff2 内联；PWA 模式下 woff2 作独立哈希文件，已加入 `globPatterns` 预缓存。

## 7. 开放技术点决策

1. **逻辑层 1:1 搬**：SmartFile/SmartFolder/TreeNode/ID3/GPS/MD5/增量扫描/撤销栈等纯逻辑，只把全局变量与 `<script>` 顺序依赖改成 `import/export`，**保留原有类与对象结构，不重写**。复杂逻辑经过验证，重写风险大。

2. **命令式 DOM 包装**：纯逻辑（Observer 调度、canvas 绘帧、坐标转换）抽 composable/service；DOM 结构用 Vue 模板；复杂交互（Modal 缩放/拖拽、Sidebar 拖拽缩放）在 `onMounted` 挂命令式监听，`onUnmounted` 清理。

3. **PWA 图标**：从 `D:\repos\相册浏览器\dist\icon.svg` 渲染生成 192/512 PNG 占位，放 `public/`，用户后续可替换。

4. **测试**：暂不加框架，靠 `npm run dev` + 用户上手验收；复杂纯逻辑（坐标转换、魔数识别、ID3）留最小 `assert` 自检片段。

5. **Pinia 边界**：store 只放跨组件应用状态；组件私有状态用 `ref`/`reactive`。

## 9. 验收策略

- **每阶段**：迁移完该阶段模块后，`npm run dev` 跑通对应验收点；用户上手主观验收 UI 体验（按用户偏好，子代理只做机械核对——DOM class、computed style、控制台报错、编译通过）。
- **双 build**：阶段 0 立项后每次大节点都跑一次 `npm run build` 确认单 HTML 不破；阶段 11 最终跑 `npm run build:pwa && npm run preview` 验 PWA 安装/离线。
- **回归**：每个阶段在 `docs/superpowers/specs/` 旁维护一份迁移进度笔记，记录已迁移模块与已知差异。

## 10. 风险与注意事项

1. **exif-js 较老**：npm 包 `exif-js@2.3.0` 多年未更新，但源码依赖它读图片 EXIF。先忠实迁移，若构建/运行有问题再评估换 `exifreader`。
2. **File System Access API 仅 Chromium**：Firefox 不支持，保留 `browser-compat` 的降级提示（`<input webkitdirectory>` 备选路径按源码处理）。
3. **两套 build 复用 `dist/`**：先跑 PWA 再跑单 HTML 会留残渣（sw.js 等）；阶段 11 验证时注意清 `dist/`。
4. **命令式 DOM 与 Vue 响应式的边界**：gallery 的卡片复用、Modal 的 LRU 缓存涉及 DOM 节点复用，迁移时需决定是用 Vue 的 `v-for` + `key` 还是保留命令式节点池。倾向 Vue `v-for` + `key`，性能问题再优化（ponytail）。
5. **`base: './'`**：两个 config 都要加，单 HTML 走 `file://`、PWA 走子路径都需要相对路径。

## 11. 不做的事（YAGNI）

- 不引入路由库（单页状态切换足够）。
- 不引入 UI 组件库（源码 CSS 自带设计系统）。
- 不引入测试框架（除非用户后续要求）。
- 不为迁移项目加 ESLint/Prettier 配置（源码有，但非本次目标；如需可后置）。
- 不重写经过验证的复杂纯逻辑（增量扫描、撤销栈、坐标转换、ID3）。
- 不预先抽象（composable 只在实际有第二个使用点时才提取）。
