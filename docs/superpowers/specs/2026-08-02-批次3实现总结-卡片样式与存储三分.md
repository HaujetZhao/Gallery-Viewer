## 二、存储三分架构重构(核心)

### 动机
原 `GalleryThumbnailDB` 只一个 `thumbnails` store;favorites/notes 用 `idb-keyval`(按 path 维度整集合);视频 duration 随文件夹快照持久化(path 维度)。问题:**同一文件在不同文件夹的副本,收藏/备注/时长各自独立、无法共享**,与缩略图(md5 内容寻址)的理念不一致。

### 目标架构:三个 IDB objectStore(均 md5 索引、懒加载)

| store | 内容 | key | 加载 | 生命周期 |
|---|---|---|---|---|
| `thumbnails`(保留) | 缩略图 blob | `${md5}_${width}` | 视窗懒加载 | LRU 清理 |
| `file-meta`(新) | 文件固有属性:duration / 宽高 / bitrate | `md5` | 视窗(与缩略图同流程) | 永久(内容稳定) |
| `user-data`(新) | 用户附加:favorites + notes 聚合 `{favorite?,note?}` | `md5` | 视窗(与缩略图同流程) | 永久,**写空删条目** |

DB 升 v1→v2(`onupgradeneeded` 加两 store,保留旧 thumbnails 兼容)。DB 名 `GalleryThumbnailDB` → `GalleryDB`(名实相符)。`idb-keyval` 从 favorites/notes 移除(handleStore/scanCache 仍用,按 root id 索引、非 md5 三分类范畴)。

### 关键设计决策
- **SmartFile model 零改动**:`duration` getter 仍读 `_meta`;`_meta.duration` 改为**运行时缓存**(由 file-meta store 懒加载或抽帧时填入)。model 层不依赖 store,符合"纯数据"约定。
- **懒加载入口**:`generateThumbnail` 内 md5 就绪后,与缩略图同流程 `ensureFileMetaLoaded` + `favorites/notes.ensureLoaded`——视窗触发,无可见延迟,内存只保留可见。GIF/SVG 无 md5(现状不支持收藏/备注,本次不动)。
- **聚合 user-data 写空删条目**:`setFavorite`/`setNote` 读改写合并,若 favorite 与 note 均空 → `deleteUserData`(保持 store 精简,全局筛选 cursor 量级小)。
- **duration 不再随快照持久化**:`fileToSnapshot`/`fileFromSnapshot` 去掉 duration 字段;旧快照 duration 字段忽略,重新从 file-meta store 加载(开发阶段不迁旧数据)。
- **user-data set\* 不读 module 级缓存做读改写源**:implementer 发现 plan 原设计会读到切根/外部改动后的陈旧值,改为每次 `getUserData` 重读(更稳健,plan 已修正)。

### 文件落点
- [db.js](../../src/services/db.js):v2 + 5 个 CRUD(`getFileMeta`/`putFileMeta`/`getUserData`/`putUserData`/`deleteUserData`,合并写、双签名)。
- [fileMeta.js](../../src/services/fileMeta.js):`ensureFileMetaLoaded`/`saveFileMeta`(填 `file._meta`)。
- [userData.js](../../src/services/userData.js):`ensureUserDataLoaded`/`setFavorite`/`setNote`/`writeUserData`(空则删)。
- [favorites.js](../../src/stores/favorites.js) / [notes.js](../../src/stores/notes.js):迁 user-data store + `ensureLoaded(md5)` 懒加载镜像(Set/Map 整体替换触发响应式);启动 `load()` 移除。
- [thumbnail.js](../../src/services/thumbnail.js):md5 就绪后接 fileMeta + userData 懒加载;移除 R11 快照 duration 置脏。
- [thumbnail-strategies.js](../../src/services/thumbnail-strategies.js):video 抽帧顺带、audio 独立 `extractAudioDuration` 写 file-meta。
- [SmartFile.js](../../src/models/SmartFile.js):快照去 duration。

## 三、关键 bug 修复(本批过程中)

1. **音频 badge 无时长** — 两因:
   - duration 抽取原挂在 `audio.generateThumbnail` 内,缩略图缓存命中时不进 → 拿不到。提到 `ensureFileMetaLoaded` 之后独立抽(与缓存解耦)。
   - `extractAudioDuration.onMeta` 内 `audio.src=''` 在读 `duration` 之前 → 清 src 后 duration 失效为 NaN,`Number.isFinite` 永 false → 不写 store。修为先存局部变量再 cleanup。
2. **rename 后时长/爱心消失** — `SmartFile.rename` 重置 `_meta`(丢 duration)+ 清 `md5=null`。但 `handle.move` 只改名、内容字节不变,md5/duration 本不该丢。改为保留 md5 + duration(外部真改内容由 `detectFileChange` 兜底)。
3. **ESC 放弃重命名误提交** — 卸载 focused input 触发 blur → commit。加 `cancelled` 守卫。
