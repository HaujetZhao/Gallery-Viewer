## R3-2+R3-3 持久化 ✅(已实现)

- **改动**:把「点击阻塞 + 每次变更全树写」拆成「点击先显示 + 变更合并 debounced 写」。
  - [services/filesystem.js](../../src/services/filesystem.js):
    - 新增 `schedulePersist(id)`:**1s trailing debounce**(`clearTimeout` 重置合并连续变更);trailing 执行时校验 `id === useRootStore().currentRootId`(切根跳过,防写错根/误清新根 dirty)。
    - 新增 `cancelPendingPersist()`:清在途 timer。
    - `handleFolderClick` 顺序改 `enrich(await) → schedulePersist(不 await) → loadFolder(await)`——点完即显示,持久化后台跑。**enrich 仍 await**(补 size/mtime 给 Gallery sort,不能挪后台)。
    - `switchToRoot`(`resetFoldersData` 前)+ `reloadProject`(`initProject` 前)入口调 `cancelPendingPersist`(防旧根 debounced 写晚到)。
    - **不改** `persistIfDirty` 自身、`scanAndPersist` 的 `await persistIfDirty`(首开全树扫后确定写)、`switchToRoot` 的 `rootEagerScan().then(persistIfDirty)`(切根 eager 扫后写新根,确定性,不 debounce)、`newBackgroundToken`。
  - [stores/history.js](../../src/stores/history.js):**顺手修预存数据丢失 bug**——`executeOperation`/`undoLastOperation` 原本只置 `rootDirty = true`、**无任何 persist 路径**(全仓仅 3 处调 persistIfDirty,都在 filesystem.js,无一在 history 操作后触发)→ rename/delete/move/undo 后关浏览器重开会丢改动。现末尾加 `schedulePersist(useRootStore().currentRootId)` 兜底落 IDB。单向依赖(history→filesystem,filesystem 不反向 import history,无循环)。
  - **测试**:+5([filesystem.test.js](../../src/services/filesystem.test.js),`vi.useFakeTimers`):点击不阻塞(推进 timer 前 loadFolder 已设 currentFolder 且 saveScan 未调)/ debounce 合并(3 次 schedule → 1 次 saveScan)/ cancelPendingPersist(取消后 0 次)/ id 校验切根跳过 / `!id` no-op。

## R3-1 缩略图首开提速 ✅(已实现)

- **改动**:提并发 + `createImageBitmap` 替 `Image+drawImage`(off-main-thread 解码,不占主线程)。
  - [config/index.js](../../src/config/index.js):`THUMBNAIL_QUEUE_SIZE` 4→**8**(+注释:可视区同时解码数 / CPU 内存富余升吃紧降 / **模块级常量启动读一次,改值需刷新页面无热改** / 8 比 12 内存吃紧时稳)。
  - [services/thumbnail-strategies.js](../../src/services/thumbnail-strategies.js):**image 策略** `new Image()+onload+drawImage` → `createImageBitmap(file, { imageOrientation: 'from-image' })`;File 来源 `peek(fileData)?.file ?? await fileData.handle.getFile()`(复用池里 ensureBlobUrl 已 acquire 的 File,不二次 IO,与 thumbnail.js 算 md5 一致);`bitmap.close()` 放 finally(drawImage 之后、toBlob 不依赖 bitmap,失败也释放)。
  - [services/thumbnail.js](../../src/services/thumbnail.js):`drawBlobToCanvas`(缓存命中还原路径,第 14-31 行)同型换 `createImageBitmap(blob, { imageOrientation: 'from-image' })`——规划没点名,但它是同型热路径(缓存命中也解码),首切提速同样受益。
  - ⚠️ **EXIF 等价性(防回归,最大风险点)**:`<img>` 元素默认 `image-orientation: from-image`(自动正 EXIF);`createImageBitmap` **默认 `imageOrientation: 'none'`**(不正)。两处都**必须**传 `{ imageOrientation: 'from-image' }`,否则带 EXIF 方向的手机照片缩略图侧躺/倒置。
  - **不动的策略**:gif(`<img>` 动画,createImageBitmap 只得首帧丢动画)/ svg(`<object>` 矢量,createImageBitmap 支持不稳)/ video(`<video>` seek 时序不可省)/ audio(冷路径,extractAudioCover 已限 5MB)。
  - md5 复用**已成立**(ensureBlobUrl 先 peek,calculateMD5 用同 File,不二次 getFile),无需改;但**读 2MB IO 仍在**(`calculateMD5` chunkSize=2MB 兼容性锁,改键换 size+mtime 会丢改名命中 + 破坏旧 IDB key 兼容,不做——规划"不做"项)。
  - **测试**:+3([thumbnail-strategies.test.js](../../src/services/thumbnail-strategies.test.js),新建,jsdom 不实现 createImageBitmap/getContext/toBlob 故全 mock):EXIF option 锁定(`toHaveBeenCalledWith(rawFile, { imageOrientation: 'from-image' })`)/ peek 命中不调 getFile + 未命中 fallback / `bitmap.close` 被调。

- **验收**:lint/test 过;待主观验(大文件夹首屏出图更快不逐个转圈 / 手机照片缩略图方向正确)。
