# 重排模式:可视化拖动重排 + 序号写回文件名前缀

日期:2026-08-06
分支:`feat/reorder-mode`

## 背景与目标

套图(单文件夹几百张)文件名命名不一致(`IMG_xxxx` / `DSC_xxxx` / 被改名过的混杂),按文件名排序后人眼顺序错乱。需要一个手动修正工具:进入「重排模式」后用拖拽把图片排到正确顺序,点「应用」把当前顺序固化成文件名前缀的数字。

**核心约束**:写回是不可逆操作(磁盘重命名)。降级只读模式整体禁用。

## 已确认的决策(brainstorming)

1. **重排起点**:进入模式即强制切「名称排序」作为起点序;模式内只挪少数错位的图。
2. **命名格式**:`NNN_原名`(下划线分隔),数字按总数定宽补零(300 张→3 位)。保留原文件名。
3. **可重复应用**:写回前剥离已有的本工具前缀(正则 `^\d+_`),不会 `001_002_xxx` 叠加。原生名如 `IMG_0042`(开头非「纯数字+下划线」)不被误剥。
4. **编号方向**:序号随模式内升降序联动。视觉顺序(从上到下 A B C D E)不变;升序→A=001..E=005,降序→A=005..E=001。即 `seq = dir==='asc' ? index+1 : total-index`。
5. **方案 A**:重排模式临时退出虚拟化,改普通 grid 全量渲染 + 复用 RootSwitcher 的原生 HTML5 drag 范式。适用几百张;>~1000 张会卡(标 `ponytail:` 注释 + 升级路径=虚拟化下 pointer 拖拽)。

## 架构

### 新增 `useReorderStore`(Pinia setup store)

重排态跨 Gallery / PhotoCard / 工具栏 / 右键菜单共享,进 store(约定 7)。

```
active: ref(false)
order: ref([])                 // 重排中的文件数组(真实视觉顺序,A B C D E)
selected: ref(Set<file>)       // 选中的 file 引用集合
direction: ref('asc'|'desc')   // 模式内方向,进入时取当前 sortDirection
savedSort: null                // 进入时快照 {field, direction},退出恢复

enter(folder):
  savedSort = { settings.sortField, settings.sortDirection }
  settings.set('sortField','name')               // 强制名称排序
  direction = savedSort.direction
  order = [...folder.files].sort(nameCompare × direction)
  active=true; selected.clear()

toggleSelect(file) / clearSelect()
moveSelectedTo(insertAt):       // 从 order 移除 selected,整体插到 insertAt
setDirection(dir):              // 只改 direction(order 视觉顺序不变,编号映射变)
cancel():                       // 恢复 savedSort;active=false;丢弃 order
apply():                        // 构造 BatchRenameOperation 并执行(见下);成功后同 cancel 收尾
```

### 新增 `src/utils/reorder.js`(纯函数,可单测)

- `padWidth(total)` → 位数(`String(total).length`)
- `padSeq(seq, width)` → `String(seq).padStart(width,'0')`
- `stripOldPrefix(name)` → `name.replace(/^\d+_/, '')`(只剥本工具格式)
- `seqForIndex(index, total, direction)` → 升序 `index+1`、降序 `total-index`
- `composeName(origName, seq, width)` → `${padSeq(seq,width)}_${stripOldPrefix(origName)}`
- `computeGridInsertIndex(clientX, clientY, cellEls)` → 多列 grid 落点(见「拖拽」)

### 新增 `BatchRenameOperation`(`src/services/operations.js`)

聚合 N 条 `{ file, oldName, newName }`。普通 `FileRenameOperation` 是单文件粒度,批量若每文件一条会塞爆撤销栈(MAX 50)且 Ctrl+Z 体验差。

- `execute()`:用 `runConcurrent` 限并发依次 `file.rename(newName)`,带进度回调;累积失败列表(不因单条失败中断整批;rename 不可逆,已成功的不回滚)。
- `undo()`:反向 `file.rename(oldName)`(用记录的 oldName;SmartFile 当前 name 已是新名,反向恢复)。
- `getAffectedFolders()`:所有 file.parent 去重。
- **冲突兜底**:新名理论上唯一(唯一序号前缀 + 各异原名);边界(原名恰好 = 他人新名,如残留的旧前缀文件)复用 `FileDeleteOperation._generateUniqueTrashName` 模式,目标目录=父夹 `handle`,冲突则 `${seq}_${base}_${counter}${ext}`。

### Gallery 双模式渲染

- 常态:现有虚拟化(`useWindowVirtualizer`)+ frozenOrder,不动。
- 重排态(`reorder.active`):**不走虚拟化**,改 `<TransitionGroup name="reorder-grid">` 全量 `v-for` `order`,普通 CSS grid 流式(`grid-template-columns: repeat(var(--col-count),1fr)`,列数沿用 `columnCount` 设置,gap 沿用)。FLIP 挤压靠 TransitionGroup 的 `-move` 过渡。
- 容器加 `@contextmenu`(空白处):`contextMenu.show` 出菜单,含「进入重排模式」项;`isDegradedFSA()` 时该项不出现。
- 重排态顶部浮工具栏:`[应用重排] [取消]` · `已选 N / 共 M` · `[升序|降序]`。

### PhotoCard 重排态行为

复用 PhotoCard(缩略图渲染不变),加 `reorderMode` prop 触发交互分支:
- 右上角选中圆圈(`reorderMode` 时显示,`selected` 高亮)。
- `:draggable` 在重排态恒 true(且非降级),但 dragstart 走重排(设标识),不走原有 move MIME(`application/x-photo-path`)。
- 点击 = `toggleSelect`(不 openPreview)。
- 悬浮不展开(重排态禁用 expand 样式与 hover 行为)。
- 右键菜单:重排态可简化(选中/取消),非必须,首版可保留原 fileMenu。

### 拖拽与多选(多列 grid)

照搬 RootSwitcher 范式,落点算法改为多列:
- `dragstart`:若拖的卡片在 `selected` 中,拖整个选中集合;否则单拖(并清空其余选中,只选该卡)。记录 `draggingSet`,快照 `order`。document 级 `dragover`/`dragenter` 持续 `preventDefault` + `dropEffect=move`(消除禁用光标)。
- `dragover`(容器级):`computeGridInsertIndex(clientX, clientY, 非-被拖 cellEls)` 算落点 `insertAt`;临时把选中集合从显示序移除、在 `insertAt` 插入 N 个「幽灵」占位 → 其余卡片 FLIP 挤压。
- `drop`:`reorder.moveSelectedTo(insertAt)` 落定。
- `computeGridInsertIndex`:遍历非被拖 cell(按 order 顺序),指针在 cell 的「左上半区」(`clientY < rect.top` 或 `clientY < rect.bottom 且 clientX < rect.center.x`)→ 返回该 cell 在「非被拖序列」中的索引;否则末尾。`ponytail: O(n) 遍历,几百张够用;万图升级=R-tree/虚拟化命中`。

### 应用流程(确认 + 进度)

- 点「应用重排」→ 打开 `ConfirmDialog`:列「将重命名 N 个文件」+ 预览前若干条 `oldName → newName`,带方向与宽度说明。确认后执行。
- 执行期间工具栏进入「处理中」禁用态;`BatchRenameOperation.execute` 的进度回调驱动一个阻塞式反馈(扩展现有 `uiToast` 或 ConfirmDialog 的 progress 样式)。
- 完成:toast「成功 N / 失败 K」(失败时提示可用 Ctrl+Z 撤销成功的部分);成功后 `apply()` 收尾(恢复排序、退出模式)。此时名称排序恢复,正好显示新前缀的正确顺序。
- 取消(不应用):直接 `cancel()`,不动文件。

### 降级与边界

- **降级**(`isDegradedFSA()`):容器右键菜单不出现「进入重排模式」;`enter()` 内 `isDegradedFSA()` 二次兜底拦截。PhotoCard `:draggable` 降级下恒 false(现有逻辑)。
- **空/单文件文件夹**:允许进入(<2 文件时「应用」置灰,无操作)。
- **模式中切走文件夹**:`currentFolder` 变 → 自动 `cancel()`(不写回),避免跨夹污染。
- **应用后 md5 不变**:rename 不改内容,md5 复用,缩略图/收藏/备注不丢(SmartFile.rename 已清 md5 缓存待重算——前 2MB 内容寻址,内容未变→重算命中缓存)。

## 风险与升级路径

- **>~1000 张卡顿**:重排模式全量渲染。升级=虚拟化下 pointer-events 拖拽(方案 B)。首版标 `ponytail:` 注释。
- **多列落点手感**:多列 grid 的「前/后」半区在行末/行首换行处可能主观别扭——属 UI 体验,留给用户浏览器实测调。
- **批量部分失败**:不自动回滚成功的(rename 不可逆批量回滚复杂),靠 undo 整体撤。失败明细 toast。
