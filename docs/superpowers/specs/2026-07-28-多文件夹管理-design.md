# 多文件夹管理 + 扫描缓存 设计

> 日期:2026-07-28。配合 [改造路线图](../../改造路线图.md)。
> 目标:在保留单根运行时模型的前提下,支持「打开过的根文件夹记录 + 秒切换 + 打开新」,并用扫描结果缓存实现切换免重新扫描。

## 背景

当前是单根模型:`openFolderPicker` 选一个根 → `initProject` 扫描 → 句柄持久化(单 handle,`handleStore`)。用户已验收单句柄恢复。

新需求:
- 打开过的根文件夹**记录下来**(多个),可在记录间**切换**。
- 仍可**打开新**文件夹。
- **单根运行时**(一次只激活一个 `currentRoot`,不并发挂载多根)。
- 切换要**秒级**(3000 文件 scan ≈ 1s,不能每次切都重扫)。

## 关键决策(brainstorming 已定)

| 决策 | 选择 | 理由 |
|---|---|---|
| 扫描结果持久化 | **保存** | 秒切换;为此改良数据结构 |
| 序列化逻辑位置 | **model 自带 rehydrate** | 内聚;序列化是纯数据操作,不违 model 纯逻辑 |
| 一致性策略 | **秒显缓存 + 后台 scan 校验** | 兼顾速度与磁盘一致 |
| 主界面切换入口 | **Sidebar 顶部切换器** | 高频操作,常驻可见,与文件树一体 |
| 历史记录上限 | 无上限 | 只存 handle+元数据,空间可忽略 |
| 移除确认 | 直接生效 | 只清记录不删文件,可重开 |

## 1. 数据层:model rehydrate

`SmartFile` / `SmartFolder` 各加一对方法,把「可持久化的数据」与「运行时状态」分离。

### SmartFile
```js
toSnapshot()                       // → { handle, name, size, lastModified, md5 }
static fromSnapshot(snap, parent)  // → SmartFile 实例(填数据 + 设 parent;blobUrl 按需重建,不在快照)
```

### SmartFolder
```js
toSnapshot()                       // → { handle, name, files:[FileSnapshot], subFolders:[FolderSnapshot], expanded, scanned }
static fromSnapshot(snap, parent)  // → SmartFolder(填数据 + 设 parent + 新建 treeNode(expanded 从快照))
```

**不进快照的运行时字段**:`parent`(重建时按传参接回)、`blobUrl`(运行时临时 URL,重启失效,缩略图/预览时按需重建)、`treeNode`(重建,但 `expanded` 从快照恢复)、方法。

**进快照的字段**:`handle`(FileSystemHandle 可结构化克隆,能进 IDB)、`name`、`size`/`lastModified`/`md5`(文件元数据)、`expanded`/`scanned`(扫描/UI 状态)。

`fromSnapshot` 必须保证:重建后的 SmartFolder 在行为上与原对象一致(scan 增量、validate、path getter 等仍可用)。

## 2. 持久化层(三层,各司其职)

### 2.1 handleStore(IDB,持久化 handle + 记录)
扩展现有单 handle 为**列表**。用 idb-keyval。
```js
// IDB key 'roots' → [{ id, handle, name, fileCount, lastUsed }, ...]
loadAll()                          // → 记录数组(含 handle + 元数据)
add(handle)                        // isSameEntry 去重 + 更新 lastUsed + 生成 id(crypto.randomUUID);返回 id
remove(id)
update(id, patch)                  // 更新元数据(fileCount/lastUsed),持久化
getHandle(id)                      // → handle(从内存记录取)
getLastUsed()                      // → { id, handle } 按 lastUsed 降序取第一个
verifyPermission(handle, mode)     // 沿用现有
```
**迁移**:启动 `loadAll()` 若空但旧 key `root-directory-handle` 存在,迁移成列表首项(保留旧 handle,fileCount=0 待扫描补),删旧 key。

### 2.2 scanCache(IDB,持久化扫描快照)
新 service。
```js
// IDB key `scan-${rootId}` → FolderSnapshot(整棵树)
load(rootId)                       // → FolderSnapshot | null
save(rootId, snapshot)
clear(rootId)
```

### 2.3 rootStore(Pinia,响应式,给 UI 读)
新建 store。**只持元数据**(handle 不进响应式 store——避免 Vue 代理 FileSystemHandle)。是 handleStore 的响应式镜像:启动从 handleStore 加载,修改时同步写回 handleStore。
```js
roots: [{ id, name, fileCount, lastUsed }]   // 响应式列表(UI 显示)
currentRootId: string | null
loadFromHandleStore()              // 启动:handleStore.loadAll() → 填 roots 元数据
add(id, name, fileCount, lastUsed)
remove(id)
updateMeta(id, { fileCount, lastUsed })   // 扫描后更新 fileCount;切换后更新 lastUsed。内部同步 handleStore.update(持久化)
setCurrent(id)
```

## 3. 切换流程(filesystem)

新增 `switchToRoot(id)`(核心):
```
1. handle = handleStore.getHandle(id); 若无 → 从 rootStore/handleStore 移除,提示
2. verifyPermission(handle):失败 → toast + 移除记录,return
3. scanCache.load(id):
   - 命中 → SmartFolder.fromSnapshot 重建整棵树 → 填 fsStore.foldersData + rootFolder + currentFolder(秒显)
   - 未命中 → initProject(handle)(正常扫描)
4. rootStore.setCurrent(id) + updateMeta(id, { lastUsed: now })
5. 后台 startBackgroundScan(fsStore.rootFolder)  // 校验(见 §4)
6. 扫描/校验完成后 scanCache.save(id, root.toSnapshot()) + rootStore.updateMeta(id, { fileCount })
```

`openFolderPicker` 改:选新 → `initProject` 扫描 → `handleStore.add(handle)`(去重) → `scanCache.save` → `rootStore.add/setCurrent` → 后台校验。

启动恢复:`handleStore.getLastUsed()` → 权限 granted 则 `switchToRoot(id)` 自动恢复;否则启动页显示"打开上次:X"(沿用现有 restorableHandle 机制,扩展为指定 id)。

## 4. 一致性:秒显 + 后台校验

切换秒显缓存后,后台用**现有 scan(增量差集算法)**遍历校验:
- 现有 scan 已能处理:文件被删(差集清)、新增(加入)、改动(size/lastModified 变 → refresh)。
- 校验 = `startBackgroundScan` 递归 scan 全树(从代理 root 起步,响应式自动更新 UI)。
- 校验完 `scanCache.save` 更新缓存 + `rootStore.updateMeta` 更新 fileCount。

> 校验期间 UI 已显示缓存(秒显),用户可立即操作;校验静默更新差异。

## 5. UI

### 5.1 RootSwitcher.vue(Sidebar 顶部,新组件)
- 固定区:当前根名 + ▼。
- 点开下拉:`rootStore.roots` 列表,每项显示 **名称(根文件夹名)· 文件数 · 最后使用(相对时间)**;当前根高亮 + 标"当前";其余点切换(`switchToRoot`),右侧 ✕ 移除(`handleStore.remove` + `rootStore.remove` + `scanCache.clear`)。
- 底部:"+ 打开新文件夹"(`openFolderPicker`)。
- 点外部/ESC 关闭下拉(沿用 ContextMenu 的关闭模式)。

### 5.2 启动页(App.vue)
- `rootStore.roots` 为空:原启动页(点开新)。
- 非空:历史卡片列表(同 RootSwitcher 信息)+ "打开新";权限需重授权时显"打开上次:X"(已有 restorableHandle 机制)。

### 5.3 名称显示
根记录只显示 `handle.name`(根文件夹名)。完整路径需 `rootHandle.resolve` 但跨根无意义,故不显示路径,只 name + 文件数 + 最后使用。

## 6. 错误处理

- **handle 失效**(文件夹被删/移动):`verifyPermission` 或 scan 抛 NotFoundError → toast 提示 + `handleStore.remove` + `rootStore.remove` + `scanCache.clear`。
- **缓存损坏**(`fromSnapshot` 抛错):catch → fallback `initProject`(重新扫描)。
- **权限拒绝**:`verifyPermission` 返回 false → toast,不切换。
- **旧 handle 迁移失败**:忽略,继续空列表(用户重新选)。

## 7. 测试(Vitest)

- **model rehydrate 往返**:`toSnapshot` → `fromSnapshot` 重建后,字段一致(files/subFolders 树、expanded、md5);mock handle(普通对象 stub `isSameEntry`/`getFile`)。
- **scanCache 存读**:mock idb-keyval,save → load 往返。
- **handleStore 去重**:add 同一 handle(isSameEntry mock)不重复。

## 8. 迁移

启动 `handleStore.loadAll()`:
- 空列表 + 旧 key `root-directory-handle` 存在 → 迁移成 `[{ id: randomUUID, handle: 旧handle, name, fileCount: 0, lastUsed: Date.now() }]`,删旧 key。
- rootStore 启动 `loadFromHandleStore` 填元数据。
