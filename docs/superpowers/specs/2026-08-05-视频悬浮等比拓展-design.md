# 视频悬浮满幅等比拓展

## 背景

视频预览卡片当前是 `aspect-ratio: 1/1` 方形容器 + `object-fit: cover`。因此：
- **横屏**视频（如 16:9）左右被裁，只显示中间竖条；
- **竖屏**视频（如 9:16）上下被裁，只显示中间横条。

用户希望在**鼠标悬浮**视频卡片时，卡片"上下或左右拓展"，把被裁掉的部分完整显示出来（看到完整视频帧）。

## 目标

- 悬浮视频卡片（仅悬浮/自动预览模式，即卡内已有播放中的 `<video>`）时，缩略图真实变为视频原始宽高比，**满幅无黑边**（容器比例 == 视频比例，`object-fit: cover` 自然满幅）。
- 只拓展视频本身，**不**需要信息条跟随；先做最小实现。
- 精确匹配视频比例（常见 16:9 → 横向约 1.78 倍、竖屏 9:16 → 纵向约 1.78 倍）。
- **不破坏虚拟化布局**：拓展只在 `transform`/`aspect-ratio` 上做，卡片在网格中的占位不变，行高/滚动/虚拟化不受影响。

## 关键洞察：拓展是单向的

精确匹配比例时，**拓展只发生在被裁的那一维**：
- `r = videoWidth / videoHeight ≥ 1`（横屏）：宽度 `= colWidth × r`，高度**不变**（保持方形时的列宽 `colWidth`）→ 只横向拓开，露出左右被裁部分。
- `r < 1`（竖屏）：高度 `= colWidth / r`，宽度**不变** → 只纵向拓开，露出上下被裁部分。

所以"上下或左右"由视频朝向自然决定，不会双向乱长，也不会改动卡片占位。

## 机制

### 1. Gallery.vue 暴露 `--col-width`

在 `gallery-grid` 的 `:style` 上暴露 CSS 变量 `--col-width`（列宽 px），供卡片算拓展尺寸。列宽 = `computeRowHeight(...) - gap`（非 detail 时 = `rowHeight - gap`；detail 时另减 `DETAIL_INFO_HEIGHT`）。已在 `measureRowHeight()` 里有现成列宽推导，挂到网格即可。

### 2. 纯函数 `computeVideoExpand`（可单测）

新增到 `src/utils/gallery-layout.js`：

```js
// 由列宽 + 视频固有尺寸算悬浮拓展几何。
// 返回 { width, height, translateX, translateY, expanded }
// - expanded=false(方形/无被裁部分)时各尺寸取默认,调用方不拓展。
// - r>=1(横屏):宽=colWidth*r,高=colWidth,仅水平居中平移
// - r<1(竖屏):高=colWidth/r,宽=colWidth,仅垂直居中平移
export function computeVideoExpand(colWidth, videoW, videoH) { ... }
```

平移量用于把溢出到邻卡的缩略图**居中回卡原位**：横向溢出默认向左（card 左对齐），需 `translateX(-(width - colWidth)/2)`；纵向同理 `translateY(-(height - colWidth)/2)`。

### 3. PhotoCard.vue 拓展逻辑

- hover（`cardHovered`，已有）且 `isVideo && videoPreviewMode !== 'thumbnail'` 时，从 `<video>` 读 `videoWidth/videoHeight`。
- 计算 `computeVideoExpand(colWidth, videoW, videoH)`，把结果以响应式值暴露给模板/样式（`--exp-w`/`--exp-h` CSS 变量挂到卡片根元素）。
- 比例来源优先实时读 `<video>`；若 hover 瞬间 `videoWidth=0`（src 异步未加载），监听 `loadedmetadata` 补一次（仍 hover 才展开）；最终拿不到 → 不拓展，优雅降级。
- 近似方形（`r≈1`）→ 无被裁部分，不拓展。

**与 isVisible 的冲突处理（用户确认）：** `playObserver` 观察 `<video>` 本身（threshold 1.0），展开后视频变大出视口 → `isVisible` 翻 false → 本会暂停。用 `videoExpanded` 状态位化解：
- **约束① 在视口外时不展开**：`videoExpanded` 仅当 `hover + isVisible(整卡可见) + 尺寸齐` 置真。
- **约束② 展开后不暂停**：`updatePlayback` 的 `shouldPlay = (isVisible || videoExpanded) && (auto || hover)`，isVisible 翻转也不停。
- `videoExpanded` **只在移开时关闭**、不随 isVisible 翻转收起 → 展开后出视口不会「收起→可见→再展开」振荡。

### 4. 样式（视频元素弹出，卡片不动）

**机制修正（用户确认）：改变的是视频预览本身的大小，中心不动，下面的卡片完全不变。** 因此不是改容器/卡片尺寸，而是让 `<video>` 元素自身变大弹出：

PhotoCard scoped CSS：
- **容器与卡片尺寸不变**（方形缩略图 + 信息条原样），只是把 `<video>` 自身扩到视频原始比例（横屏拓宽/竖屏拓高）。
- `<video>` **绝对定位 + 居中**（`left:50%; top:50%; transform: translate(-50%,-50%)`），任何尺寸都以容器中心为基准、中心天然不动；脱离文档流 → 不参与布局，不撑高卡片/所在行（否则 grid 行高被拉伸，整行卡片都变高）。
- `.photo-card.video-expanding, .photo-card.video-expanding .thumbnail-container { overflow: visible }`——否则弹出的视频被卡/容器 `overflow:hidden` 裁掉。
- `.photo-card.video-expanding .thumbnail-video { width: var(--exp-w); height: var(--exp-h); z-index: 20 }`——弹出层盖过卡内 fav/badge/note/info（z-index 2~5）。
- **`max-width: none`**：Tailwind preflight 的 `img,video { max-width:100% }` 会把悬浮拓宽的视频钳到容器宽、横向溢出被裁；显式关掉才能横向覆盖邻卡（纵向不受影响，故之前只有横向不见）。
- **不隐藏信息条**（卡片完全不动，信息条保持原样，只是可能被弹出视频短暂盖住）。
- 依赖既有 `z-index:10` + hover 上浮，弹出部分覆盖邻卡（非 hover 卡 `z-index` auto，同 stacking context 内 10 > auto）。
- 基础 `.thumbnail-video` 加 width/height 过渡，展开与收起都平滑。

## 布局安全性

- 卡片仍占网格 1 格，行高/`rowHeight`/虚拟化 `estimateSize` 全不受影响。
- `--col-width` 变化（ResizeObserver/列数/卡片样式变化重测 `rowHeight`）需同步刷新变量，由 Gallery 的既有 watch 链驱动。
- 横向拓展溢出到邻卡、纵向拓展溢出到下一行，靠 z-index 覆盖；`gallery-row`/`gallery-track`/`gallery-container` 均无 `overflow:hidden`，溢出可见。
