## 任务 R5 · 视频自动播放 + 时长回填（不存进度）

**前置：R12 已完成**（媒体渲染在 `MediaView` 子组件内）。

**目标**：modal 当前媒体是视频时，**打开或左右切换到它都自动播放**；浏览器拦截带声播放则**静音继续播放**。**不做进度持久化**（currentTime 由 R12 的 `<KeepAlive>` 保留 DOM 隐式继承，够用）。顺带在视频加载时**回填缺失的 `_meta.duration`**（解决 R11 老缓存视频时长为空的边界）。

**改法**（在 `MediaView` 视频元素上）：
1. `@loadedmetadata`：
   - 调 `detectFileChange(file)`（R3 已有，[SmartFile.js:149](../../src/models/SmartFile.js#L149)）检测 size/mtime 变更、清 md5。
   - **时长回填**：若 `file.duration == null` 且 `Number.isFinite(video.duration)` → 写 `file._meta.duration = video.duration` + `afterTreeMutation(currentRootId)` 置脏持久化（同 R11 的 [thumbnail.js:80-81](../../src/services/thumbnail.js#L80-L81) 套路）。
2. **自动播放**：`loadedmetadata` 后调 `video.play()`；`play()` 被 reject（NotAllowedError = 浏览器拦带声）→ `video.muted = true` 后再 `play()`（静音续播，用户可手动取消静音）。其它 reject（AbortError 切换中断等）静默忽略。
3. **切换走时暂停**：`<KeepAlive>` 的 `onDeactivated` 钩子里 `video.pause()`（避免离开后音频继续）。`onActivated` 时若是当前项，重新触发上述自动播放流程。

**边界**：图片/svg/音频不受影响；`play()` 的 promise 都要 `.catch(()=>{})` 兜底，绝不抛未处理 rejection。

**验收**：打开视频自动播；被拦则静音播；左右切到视频也自动播；切走停止；主观手感用户验。客观可断言 loadedmetadata 后 video.paused===false。

## 任务 R8 · 会话内稳定排序（冻结顺序）

**目标**：rename/delete/move/enrich 不再即时重排（文件"飞走"）；只有①刷新页面 ②切走再切回（currentFolder 变）③点侧栏文件夹 ④用户改排序方式 时才重排。会话内新进入的文件追加末尾。

**现状**：[Gallery.vue:23-37](../../src/components/Gallery.vue#L23-L37) `displayFiles` computed 按 `name/size/lastModified` 实时重排。

**改法**：
1. **冻结机制**：给当前视图的文件盖一个稳定序号。用一个 `frozenOrder: Map<file.path, number>`（或给 file 挂非响应式 `__order`），冻结时按"当前排序键"算出有序列表、依次赋递增序号。
2. **`displayFiles` 改为按 `frozenOrder` 排序**（稳定），不再读 live name/size/mtime。搜索过滤仍按 debouncedTerm 实时（过滤与排序正交，过滤只隐藏、不改变相对序）。
3. **冻结触发点**（在这些时机重建 frozenOrder）：
   - `currentFolder` 变化（切走再切回、点侧栏）；
   - 用户改 `sortField` / `sortDirection`（[userSettings](../../src/stores/userSettings.js)）→ 立即重冻；
   - 手动刷新（reload/refresh）。
4. **size/date 的"沉淀"**：name 排序进入即冻；**size/date 排序**进入时先冻一次，待**当前 folder 的 enrich 完成后**（_meta 补齐）**再重冻一次**，之后冻结直到下一触发点。实现：一个 per-load 的 `settled` 标志，enrich 完成（当前 folder 全部 file 有 `_meta`，或首个 enrich pass 结束）后若未 settled → 重冻 + 置 settled。（此条最需现场把握信号，建议用"currentFolder 首个 enrich pass 完成后重冻一次"。）
5. **新进入文件追加末尾**：会话内当前 folder 出现新 file（R2 后台扫描 `integrateScanResult` 的 `newFiles`、或 move-in）→ 给它赋 `__order = 当前最大值+1`，不触发整体重冻。需在 integrateScanResult 写回当前 folder 时给 newFiles 补序号（或 Gallery watch files 长度变化时给无序号的新项补）。
6. **ALL_MEDIA 聚合视图**同样适用（[switchToAllPhotos](../../src/services/folderActions.js) 的 allMediaFolder.files 进入视图时同套冻结）。

**边界**：跨"切走再切回"必须重冻（这是用户显式期望的"刷新点"）；rename 后文件留原位、只换 name 显示。

**验收**：rename 后文件不跳位；切走切回才重排；改排序方式立即重排；移入/扫描新增的文件出现在末尾。客观可测：rename 一个文件断言其在 displayFiles 中索引不变（同 sortField=name 下）。

## 任务 R10 · 三态展开（收起 / 展开单层 / 递归展开）

**目标**：侧栏文件夹图标点击三态循环：**收起 → 展开单层 → 递归展开 → 收起**。

**现状**：[SidebarTreeItem.vue:94-97](../../src/components/SidebarTreeItem.vue#L94-L97) 图标 `@click` 调 `toggleExpanded()`（[SmartFolder.js](../../src/models/SmartFolder.js) 的实例方法，两态翻转）。`expanded` 布尔随快照持久化。

**改法**：
1. **语义**（用户已确认"展开单层强制收起后代"）：
   - **收起**：`folder.expanded = false`
   - **展开单层**：`folder.expanded = true`；**所有后代 `expanded = false`**（强制只看一层）
   - **递归展开**：`folder.expanded = true`；**所有后代 `expanded = true`**
   - 循环：收起→单层→递归→收起。当前态判定：`!expanded`=收起；`expanded && 所有后代都 expanded` → 视为递归态；`expanded && 存在未展开后代` → 视为单层态。
2. **新方法**（SmartFolder 模块级或实例方法）：`cycleExpand()` 实现上述循环（沿 subFolders 递归设后代 expanded）。
3. **图标三态可视化**：收起 `fa-folder` / 单层 `fa-folder-open` / 递归 `fa-folder-tree`（确认 font-awesome 有 `fa-folder-tree`，无则换可用的多层图标）。
4. SidebarTreeItem 图标 `@click` 改调 `cycleExpand()`；`aria-expanded` 保留布尔（无障碍按展开/收起两态足够）。

**边界**：叶子文件夹（无 subFolders）点击无视觉变化（无可展开内容）；持久化（expanded 沿树写入）随 schedulePersist 落盘。

**验收**：三态循环正确、强制收起后代生效；图标区分三态；主观观感用户验。

## 任务 R12 · modal DOM 缓存（KeepAlive，LRU 10）

**目标**：保留最近 ~10 个媒体的 DOM（含视频），回看瞬开、无 load 闪烁、视频 currentTime 隐式保留。原版方案见 `D:\repos\相册浏览器\js\modal.js`（LRU Map 容量 10）；Vue3 用 `<KeepAlive :max="10">` 等价实现，更地道。

**现状**：[MediaModal.vue](../../src/components/MediaModal.vue) `<Teleport><div v-if="modal.isOpen">…<img>/<video>/…</div></Teleport>`——关闭即销毁 DOM；切换是单元素换 src。

**改法**：
1. **抽 `MediaView` 子组件**：把 image/video/svg/audio 的渲染（含 R3 的 detectFileChange、R5 的自动播放/时长回填）从 MediaModal 搬进 `MediaView.vue`，props 接 `file`。该组件按 mediaKind 渲染对应元素。
2. **`<KeepAlive :max="10">`**：MediaModal 内
   ```html
   <KeepAlive :max="10">
     <MediaView :key="mediaKey" :file="modal.currentFile" />
   </KeepAlive>
   ```
   - `mediaKey` = `file.path`（会话内稳定；rename 后 miss 可接受，缓存本就会话内）。KeepAlive 按 key 缓存组件实例（DOM+状态），LRU 10，超出自动卸载最旧。
   - 视频 currentTime 由组件实例存活隐式保留（与原版同），**无需专门存进度**。
3. **modal 容器 `v-if` → `v-show`**：`<div v-show="modal.isOpen">`（保留 Teleport）。**关键**：v-if 会在关闭时销毁 KeepAlive 及其全部缓存；改 v-show 才能让缓存跨"关掉再打开"存活（原版 close() 不清缓存的等价语义）。
4. **useModal 的 mediaEl ref 协调**：useModal 现靠 `mediaEl` ref 做平移/缩放/键盘（[useModal.js](../../src/composables/useModal.js)）。抽组件后，active media 元素需能被 useModal 拿到——用 `defineExpose` + ref 转发，或 MediaView emit 挂载时把根元素注册给 useModal；切换时（KeepAlive activate）更新指向。
5. **onDeactivated 暂停**：MediaView 内视频/音频在 `onDeactivated` 暂停（R5 协同）。

**边界**：Teleport 目标不变；loading/loader 覆盖层逻辑保留；缓存的 blobUrl 依赖 fileResource 池——确认池对当前可见 + 缓存中的文件不回收（若池会回收，需在缓存存活期间 hold 引用，防 blobUrl 被 revoke）。

**验收**：切走再切回同一张瞬开（无 load 闪烁）；关掉 modal 再打开同一张仍瞬开；视频回看进度在；缓存超 10 淘汰最旧；主观手感用户验。客观：切回断言 `<img>` 不触发 load 事件（DOM 复用）。

## 任务 R14 · md5 备注（hover tip + 属性面板编辑）

**目标**：以 md5 为 key 存多行备注；卡片 hover 时**仅当有内容**显示自定义 tip；属性面板有"备注"栏，点一下进入 inline 编辑（同文件名编辑），失焦或 `Ctrl+Enter` 完成。

**改法**：
1. **notes store**（`stores/notes.js`，setup 风格，同 [favorites.js](../../src/stores/favorites.js) 套路）：内存 `Map<md5, text>` + idb-keyval 持久化（key 自定如 `'notes'`）；`get(md5)` / `set(md5, text)`（空串视为无备注、删除 key）/ `has(md5)` / 启动 `load()`。响应式靠整体替换 Map 触发（同 favorites）。
2. **App.vue** `onMounted` 调 `notes.load()`（同 favorites.load）。
3. **卡片 hover tip**（[PhotoCard.vue](../../src/components/PhotoCard.vue)）：`notes.has(file.md5)` 为真时，hover 显示自定义浮层（多行、白底、定位卡片上方/下方）。**仅 md5 有备注才显示**；无 md5 / 无备注不显示。tip 用自定义 div（非原生 title，要多行+样式），hover 进出控制显隐。
4. **属性面板**（[PropertiesPanel.vue](../../src/components/PropertiesPanel.vue)）：加"备注"行，**复用文件名那套 inline 编辑模式**（先读 PropertiesPanel 看文件名怎么做的：点文本→变输入框、失焦提交、`Ctrl+Enter` 提交）。备注用 `<textarea>` 多行；提交时调 `notes.set(file.md5, value)`（空串 → `notes.set(md5,'')` 即删除）。属性面板打开时按当前文件 md5 读备注。

**边界**：md5 未算（未进视窗/刚打开）的文件，属性面板备注栏可显示但保存时若无 md5 → 提示需先生成/或等 md5 就绪（简单处理：md5 缺失时备注栏只读 + 提示）；多行文本原样存取。

**验收**：属性面板可编辑多行备注、Ctrl+Enter/失焦提交、刷新仍在；卡片 hover 有备注才显 tip；客观可测 notes store set/get/has + 持久化。

## 任务 R15 · md5 哈希迁 Web Worker（治滚动卡顿）

**目标**：把 `SparkMD5` 哈希从主线程搬到 Web Worker，消除快速滚动时多卡进视窗算 md5 导致的掉帧。

**现状**：[file.js:6-10](../../src/utils/file.js#L6-L10) `calculateMD5` → `SparkMD5.ArrayBuffer.hash(buffer)` **同步主线程**。调用点 [thumbnail.js:53-56](../../src/services/thumbnail.js#L53-L56)（视窗触发生成缩略图时）。缩略图解码（`createImageBitmap`）已离主线程，本任务**只搬 md5**（resize/toBlob 进 worker 列为后续进阶，不做）。

**改法**：
1. **新建 worker**（Vite 原生：`src/utils/md5.worker.js`，`new Worker(new URL('./md5.worker.js', import.meta.url), { type: 'module' })`）。worker 内 import `spark-md5`，收 `ArrayBuffer` → `SparkMD5.ArrayBuffer.hash` → postMessage 回 hash。
2. **传参**：主线程读出 `file.slice(0, 2MB).arrayBuffer()` 后，**transfer**（零拷贝）进 worker（不在 worker 里 slice，主线程读好传 buffer）。
3. **`calculateMD5(file)` 改为异步走 worker**：返回 Promise；内部用 worker 池/单 worker。**单 worker + 队列**（够用；想榨多核再上池）。
4. **in-flight 去重**：快速滚动可能对同一文件在 md5 算完前重复请求 → 维护一个 `pending: Map<key, Promise>`（key 用 file/path/size），命中复用同一 Promise，避免重复算。算完删除。
5. **生命周期**：worker 单例、应用期常驻；保留 `calculateMD5` 的对外签名（返回 Promise<string>），调用方 [thumbnail.js](../../src/services/thumbnail.js) 改 `await`（原已是 async，签名兼容）。

**边界**：`chunkSize=2097152` 锁定不变（旧 IDB key 兼容）；worker 不可用时（极端）回退主线程算（兜底）；transfer 后主线程该 buffer 失效，注意别复用。

**验收**：滚动顺滑（主观，用户验）；md5 结果与改前一致（客观测：同一文件 hash 不变）；并发不重复算（可测 pending 去重）。
