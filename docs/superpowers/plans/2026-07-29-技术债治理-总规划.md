# 技术债治理 · 总规划(Master Plan)

> **架构师周期**:2026-07-29 起,基于「第一性原理审查报告」(见 [specs/2026-07-29-架构重构-round4-第一性原理审查与model函数化.md](../specs/2026-07-29-架构重构-round4-第一性原理审查与model函数化.md) 同源审查结论)。
> **工作流**:架构师(主会话)下发单轮任务文档 → 执行者(新上下文窗口)按文档完成 + 写变更技术报告 → 回主会话审核 → 派发下一个任务。
> **范围边界**:打技术债、顺 Vue 而为、真正分层、弥补工程缺口。**功能缺口(多选 / 批量 / 虚拟相册 / 标签 / 评分 / 幻灯片等)本轮一律不做。**

## 一、目标与已定决策

### 目标
打掉审查报告中的六个跨层根因,让代码「顺 Vue 而为 + 真正分层」,补齐工程缺口(可访问性、错误边界、测试覆盖、CSS 隔离)。**功能不增,行为等价优先。**

### 三条已定决策(架构师 × 产品负责人)
| 决策 | 选择 | 影响 |
|---|---|---|
| CSS 策略 | **Tailwind v4 + 少量自定义 CSS** | 令牌即 class,从结构上消灭硬编码/令牌纪律/全局表三大负担;复杂动画/渐变用 `@layer` 补(约 20%)。→ 决定 Phase 4 整条线 |
| 任务粒度 | **中等** | 强相关小任务合并一轮,高风险大任务单独一轮。预计 16 轮 |
| 重构深度 | **全做** | 含 Phase 2(干掉 foldersData Map → 单 ref 持树)、Phase 3(model 恢复实例方法)。高风险任务拆细 + 重点测试 + 独立分支可回滚 |

### 治理原则(每个任务都守)
1. **行为等价优先**:除「修真 bug」任务(T02)外,重构必须保持可观测行为等价,靠测试 + 客观断言 + 产品负责人主观验收兜底。
2. **TDD**:先写/改测试再改实现(单轮任务文档遵循 `writing-plans` 格式)。
3. **小步 commit**:每轮多个小 commit,任一步可回滚。
4. **优先踩巨人肩膀**:有成熟库能显著降低技术债/认知负担就引入,不为「依赖少」而自造轮子(自造须明显更优)。已核实:除 CSS→Tailwind 外,`runConcurrent`/`cancelToken`/`calculateMD5` 等自造都有合理理由(原生/现成库替代不了组合需求),不换。
5. **维持纯 JS**:本轮不引入 TypeScript。
6. **文档同步**:涉及约定变更的任务,同步更新 [CLAUDE.md](../../../CLAUDE.md) 对应条目(审查发现文档与代码已有偏差,治理中持续纠正)。

## 二、工作流约定

### 文档体系

|---|---|---|

### 每轮交付物(执行者回交主会话审核)
1. **代码改动**:git diff(分支或小步 commit)。
2. **变更技术报告**:改了什么 / 为什么 / 涉及文件(带行号)/ 测试情况 / 验收点(客观断言)/ 遗留或风险。
3. **验收基线结果**:lint / test / 双 build 的实际输出。

### git 约定
- 每轮一个分支 `debt/T<NN>-<短名>`,或 master 上小步 commit(执行者自选)。
- **高风险任务(T06 / T08)必须用独立分支**,便于整体回滚。

### 验收基线(每轮必过)
- `npm run lint` 通过(或仅剩任务文档显式批准的告警)。
- `npm run test` 通过。
- `npm run build` + `npm run build:pwa` 双 build 通过。
- ⚠️ **环境注意**:build / test 在某些环境会因 Node24 + Vite5 崩溃、或 jsdom runner 竞态跑不通——这是**环境问题不是代码问题**。若遇崩溃,在报告里记下报错原文,回主会话问架构师,**别反复重试**。

### UI 验收分工
- **客观断言**(DOM class、computed style、z-index、控制台报错、编译是否通过):执行者 / 子代理做。
- **主观体验**(过渡手感、互斥体感、布局观感、键盘操作体感):**产品负责人本人在浏览器上手判断**。单轮任务文档会列出「在哪些点验收」。

## 六、分 Phase 详述

### Phase 0 · 清理止血(零/低风险,立刻收益)
- **T01 清理**:删 `getConfig` / `safelyExecute*` / `getDB` 等(执行者须再次 grep 核实零调用,**不可盲删**);合并重复 ID3 头解析(抽 `id3.js`)、`formatBytes/formatFileSize`、`calculateMD5` 改 async/await。纯减法。
- **T02 撤销 bug**:① `switchToRoot` 成功后调 `history.clear()`(防跨根撤销动错磁盘);② `undoLastOperation` 改「先 `await op.undo()` 成功再 pop」+ 失败不落盘。带测试。
- **验收**:lint/test/build 全过;手动验证「根A删文件→切根B→Ctrl+Z 不再越界」。

### Phase 1 · 持久化机制顺 Vue(中风险)
- **T03 拆模块**:`filesystem.js`(418 行/15 导出)→ `persistence.js`(schedule/flush/cancel/persistIfDirty + timer)+ `scanIntegration.js`(integrate/register/代理化)+ `folderActions.js`(openFolderPicker/switchToRoot/reload/CRUD)。**纯物理移动,行为零变化**,全量回归测试。
- **T04 $subscribe**:fsStore.$subscribe 自动 debounce → persistIfDirty;删 `rootDirty` 字段、3 处手动置脏、integrateScanResult 脏检测;`flushPendingPersist` 改为 await 当前 debounce。状态机从 7 概念降到 3(persist/flush/cancel-on-reload)。
- **验收**:重点测切根前 flush、关浏览器(visibilitychange)、reload cancel 三条路径不丢数据、不写错根。

### Phase 2 · 数据模型顺响应式(高风险,核心)
- **T05 path 迁移**:新增纯函数 `findFolderByPath(root, path)`,替换所有「查询用途」的 `foldersData.get(path)`;Map 此后只剩「注册代理」职责。
- **T06 单 ref 持树(核心,高风险)**:`rootFolder = ref(整棵树)` 深代理覆盖全部 subFolders/files;删 `foldersData` Map、`registerAndIntegrate`、`registerFolderTree`、`resetFoldersData`、5 处「必须取代理」警告;ALL_MEDIA 虚拟文件夹重新安置。**消灭全项目最大单一负担源。**
- **T07 history 瘦身**:store 不再 import schedulePersist / 置 rootDirty(由 $subscribe 兜底);store 只管「记录 + 回放」。
- **保护**:T06 必须独立分支 + 拆成多个 TDD 小步(任务文档细化)+ 重点测试 scan/enrich/snapshot/切根/多文件夹全链。
- **验收**:后台异步任务改 store 对象不再需要「取代理」;切根秒显 + 深层按需校验行为不变。

### Phase 3 · model 行为回 class(高风险)
- **T08**:`SmartFile.move/rename`、`SmartFolder.addFile/removeFile/delete/toggleExpanded` 回到 class 实例方法;消灭「半半设计」(getter 在类、行为在模块)+ `moveFile` 绕门面直接 splice 的循环依赖尴尬 + 删除走门面/移动绕门面的「双风格并存」。`scanFolder/enrichFolder/folderToSnapshot` 等**纯算法留模块级**。算法不变,测试基本平移。
- **保护**:独立分支;算法层(scan/enrich/snapshot/池)不动,只搬行为归属。
- **验收**:门面在组件层守得住;`file.move(target)` 比 `moveFile(file, target)` 好读;无循环依赖。

### Phase 4 · UI 基础设施 + Tailwind(工程缺口)
- **T09 引入 Tailwind v4 + 令牌映射**:装 `tailwindcss` + `@tailwindcss/vite`;主 CSS `@import "tailwindcss"` + `@theme` 把 [variables.css](../../../src/styles/variables.css) 的颜色/间距/圆角/阴影令牌映射成 Tailwind theme;dark mode 配 `@custom-variant dark (&:where([data-theme=dark],[data-theme=dark] *))`。**不改任何组件**,只搭骨架,令牌双轨并存(旧 CSS 仍工作),为 T10/T14 铺路。
- **T10 主题统一 + z-index**:删 3 处 `prefers-color-scheme: dark` 硬编码块,改在 `@theme`/`@layer` 里用 `[data-theme="dark"]` 覆盖令牌(Tailwind dark variant 消费);修 z-index 同级冲突(modal=toast、contextMenu=confirm)。**修用户可直见的画面分裂。**
- **T11 useOverlay**:抽 composable 收口 ESC/点外/焦点陷阱/滚动锁,替换 RootSwitcher/ContextMenu/SettingsPanel/ConfirmDialog 四份重复 addEventListener。
- **T12 RenameInput + useFileActions**:抽 `RenameInput.vue` 去重重命名逻辑;`useFileActions` 统一右键菜单项注册(替代各组件现场拼菜单)。
- **T13 可访问性**:PhotoCard 可 tab 聚焦 + 键盘打开预览;浮层 `role="dialog"`/`aria-modal` + 焦点陷阱 + 关闭归还焦点(依赖 T11);SidebarTreeItem `role="treeitem"`/`aria-expanded`;`:focus-visible` 样式。**工程缺口(非功能)。**
- **T14 逐组件迁移 Tailwind**:把按旧文件名组织的 2150 行全局组件样式,逐组件换成 utility class;复杂动画/渐变/shake-pulse 等用 `@layer`/`@apply` 或少量 `<style scoped>` 补(约 20%);迁移完清空全局组件样式表。**改动面最大、视觉回归风险高,任务文档必拆多轮小步 + 每步视觉 diff。**
- **验收**:主题切换无分裂;浮层 z 序正确、ESC/点外一致;键盘可达;主观体验由产品负责人验收。

### Phase 5 · 测试与工程收尾
- **T15 补测试**:file.js 魔数解析(WebP/JPEG 位运算,易回归)、撤销栈全路径、$subscribe 持久化、findFolderByPath。
- **T16 错误边界 + 三态**:`onErrorCaptured` 全局兜底(替代散落的 try/catch + toast);加载/错误/空三态完善。
- **验收**:关键算法有测试护栏;未捕获异常有全局兜底不白屏。
