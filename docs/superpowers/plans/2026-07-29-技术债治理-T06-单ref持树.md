# T06 · 单 ref 持树 + 删 foldersData Map(最高风险核心)

> **For agentic workers:** REQUIRED SUB-SKILL: 用 `superpowers:executing-plans` 或 `subagent-driven-development` 按步执行。步骤用 `- [ ]` 跟踪。
> **父规划:** [2026-07-29-技术债治理-总规划.md](2026-07-29-技术债治理-总规划.md)
> ⚠️ **最高风险任务**:必须用独立分支 `debt/T06-单ref持树`,拆 TDD 小步,每步测试绿才下一步,可整体回滚。

**Goal:** 删 `fs.foldersData` Map,`rootFolder` 单 ref 深代理持整棵树,消灭「set Map → get 取代理」的代理陷阱 + `registerFolderTree` / `registerAndIntegrate`。

**Why:** foldersData 身兼查询(T05 已迁 findFolderByPath)+ **代理陷阱收口**(set 原始 folder → get 取代理)两职。代理陷阱是全项目最大认知负担源(5 处「必须取代理」警告 + registerAndIntegrate 收口函数)。单 ref 持树后,folder 挂到树即被 Vue 深代理自动代理化,不再手动 set/get。

**关键认知(架构师读代码确认):**
1. `rootFolder = ref(null)` 已是深代理——赋值 `fs.rootFolder = root` 后,root 及其 subFolders/files 全被代理。当前 foldersData 的 folder 也是代理。**T06 把 folder 从「Map 值」改为「树节点」,代理对象总数不变 → 性能风险可控**(但须冒烟验证万图)。
2. folder 挂到树(作 `subFolders` 元素或 root 本身)后被深代理 → 代理化。后台任务改「树里的 folder 引用」即写代理。**这是消灭代理陷阱的原理。**
3. T05 遗留 2:`getFolderData` 只建根,其查询/parent 分支是死代码 → T06 顺势简化它为「只建根」。

**Architecture:**
- [fs.js](../../../src/stores/fs.js):删 foldersData。
- [scanIntegration.js](../../../src/services/scanIntegration.js):resetFoldersData 改递归 dispose 树;删 registerFolderTree;integrateScanResult 删 Map set/delete;删 registerAndIntegrate;新增 disposeFolderTree。
- [folderActions.js](../../../src/services/folderActions.js):getFolderData 简化(只建根);switchToRoot 删 registerFolderTree;switchToAllPhotos 遍历树聚合;refreshFolder 从 parent.subFolders 删。
- [recovery.js](../../../src/services/recovery.js):newSubFolders 取代理改从 validAncestor.subFolders find。

**Tech Stack:** Vue 3 + Pinia + Vitest

  const fs = useFsStore();
  const parts = await fs.rootHandle.resolve(dirHandle);
  const path = [fs.rootHandle.name, ...parts].join('/');
  const folderData = findFolderByPath(fs.rootFolder, path);
  if (folderData) { folderData.handle = dirHandle; return folderData; }
  const pathParts = path.split('/');
