## 项目约定（执行前必读，否则会踩坑）
- **model 纯数据 + 同文件模块函数；副作用归 service**（[CLAUDE.md](../../CLAUDE.md) 约定 1）。`models/` 不 import Pinia/Vue、不反向依赖 store。SmartFile/SmartFolder 字段 + 派生 getter 保留（响应式追踪属性访问），模板用的 getter **勿函数化**。
- **资源走 fileResource 池**：blobUrl/File 经 `acquire`/`destroy`/`peek`。**不要直接 `URL.createObjectURL`/`revokeObjectURL`**。size/mtime 单源在 `SmartFile._meta`（响应式），不进池。
- **持久化走 schedulePersist**：改树置 `fs.rootDirty=true` + `schedulePersist(id)`，**不要直接 saveScan**。多根记录的真源是 `handleStore`（IDB `roots` 有序 cache），`rootStore` 是响应式镜像，改顺序两边都要同步。
- **后台异步任务改 store 对象必须从 store 取代理**（`fs.rootFolder` / `foldersData.get(path)`），勿用 createFolder 返回的原始对象。
- **import 省略 `.js` 扩展名**。
- **UI 主观体验由用户验收**；客观断言（DOM class、computed style、控制台报错、编译/lint 通过）可写代码核对或测试。Vitest 测试用 `npm run test`，lint 用 `npm run lint`。

## 任务 R1 · 根切换列表拖拽排序

**目标**：下拉列表里的根条目可整行拖拽手动排序；点击仍切换根。顺序持久化（切根/重启不变）。

**现状**：
- [RootSwitcher.vue:61-84](../../src/components/RootSwitcher.vue#L61-L84) 渲染 `rootStore.roots`，每项 `.root-item`（末尾 `.root-add` 是"打开新"，不参与拖拽）。
- 顺序真源 = [handleStore.js](../../src/services/handleStore.js) IDB `cache`（有序）；[root.js](../../src/stores/root.js) 是响应式镜像，**无 reorder 方法**。

**改法**：
1. **handleStore 加 `reorder(ids)`**：按传入的 id 顺序重排内存 `cache` + `persist()`。
2. **root store 加 `reorder(ids)`**：按 id 顺序重排 `roots.value` + 调 `handleStore.reorder(ids)`（与 `updateMeta` 同款"两边同步"）。
3. **RootSwitcher.vue**：给 `.root-item`（不含 `.root-add`）加原生 HTML5 拖拽（复刻 [PhotoCard.vue:64-69](../../src/components/PhotoCard.vue#L64-L69) 的 `draggable="true"` + dragstart/dragover/drop）：
   - `@click` 仍 = `onSwitch`（切换根）。浏览器按"指针是否移动"区分点击/拖拽，**不长按**。
   - `dragstart` 记下被拖 id；`dragover.prevent` + 计算落点（被悬停项的上/下半决定插前/插后）；`drop` 得到新顺序 id 数组 → 调 `rootStore.reorder(ids)`。
   - 拖拽中视觉：被拖项半透明（opacity .4）+ 蓝色插入线指落点（可用 `dragOver` ref 态控制 class）。
4. **底部"打开新文件夹"（`.root-add`）保持固定、`draggable=false`**。

**边界**：拖到自己原位 = 无操作；拖到唯一项 = 无变化；空列表态不受影响。

**验收**：拖动改顺序、刷新页面/切走切回顺序保留；点击仍正常切换；主观手感用户验。

## 任务 R2 · 切根后递归深层扫描（名字集合校验）

**目标**：切到已有根（秒显快照后），后台**递归整树**做名字集合校验，变了的对新增文件 enrich；不再只扫根一层。

**现状**：
- [folderActions.js:140-141](../../src/services/folderActions.js#L140-L141)：`restoredFromSnap` 时只调 `rootEagerScan`（[folderActions.js:54-61](../../src/services/folderActions.js#L54-L61)，**仅根一层** `scanFolder(trust:true)` + `enrichFolder`）。
- 全树递归扫描已有 `startBackgroundScan`（[folderActions.js:168-192](../../src/services/folderActions.js#L168-L192)，并发 + trust + 可取消），但切根快照路径没调用它。
- `scanFolder(trust:true)` 名字集合一致零 IO（[SmartFolder.js:296](../../src/models/SmartFolder.js#L296)），变了才差集；`integrateScanResult` 检测增删置 `rootDirty`。

**改法**：
- `restoredFromSnap` 分支：把 `rootEagerScan(...).then(persistIfDirty)` 换成走 `startBackgroundScan`（全树）+ `persistIfDirty(id)`。可抽一个和 `scanAndPersist` 同构的小函数（注意 `newBackgroundToken` 取消上一轮、从 store 取代理 root）。
- **不引入 `detectMetaChanges`、不做内容"改"检测**（"改"由 R3 在 modal 处理）。

**边界**：切根被新切换打断（token.cancelled）→ 不存旧快照（沿用现有 `scanAndPersist` 的判断）；大树后台并发受 `SCAN_FOLDER_CONCURRENCY` 约束，不阻塞秒显。

**验收**：切根后深层文件夹的磁盘新增/删除会被后台拾取（不点开也反映）；名字没变的文件夹零 IO；客观可写测试：mock scanFolder 返回 newFiles → integrate 后 store 有新增。

## 任务 R3 · modal 打开时检测文件"改"（清 md5）

**目标**：打开媒体时顺手比对 size/mtime，变了就清 md5，让缩略图机制自动重算。

**现状**：
- [MediaModal.vue:23-36](../../src/components/MediaModal.vue#L23-L36) `watch(currentFile)` 已 `ensureBlobUrl(f)`；视频/图片直接读 `f.blobUrl`。打开 modal 必然 acquire 了 File（池里 peek 有）。
- `_meta`（size/lastModified）单源在 SmartFile；`detectMetaChanges`（[SmartFolder.js:200-224](../../src/models/SmartFolder.js#L200-L224)）已实现"读 getFile + 比 _meta + 变则清 md5"——但它一次读一整个 folder，不适合单文件。缩略图重生依赖 md5 被清后 useThumbnail 视窗重算。

**改法**：
- 在 `watch(currentFile)` 拿到 `f` 后（已 ensureBlobUrl），对**单文件**做：`getFile()` 读 size/mtime → 与 `f._meta` 比 → 变则更新 `_meta` + `f.md5 = null`。可写个 `models/SmartFile` 模块级 `detectFileChange(f)` 纯函数（getFile + 比 + 写字段，不碰 store），modal 里调。
- md5 清空后，当前 modal 显示的是大图（非缩略图），不影响；**卡片缩略图**在该 file 下次进视窗时由 useThumbnail 重算（验证 useThumbnail 对 md5 变 null 的响应；如不响应，触发对应卡片重绘）。

**边界**：`_meta` 不存在 → 补上（同 detectMetaChanges）；getFile 失败 → warn 不抛；md5 本就 null（GIF/SVG 无 md5）→ 跳过。

**验收**：改一张图内容（同路径覆盖）→ 打开 modal → 关闭 → 该卡片缩略图更新；客观可单测 `detectFileChange`（mock getFile 返回变 size → 断言 md5=null + _meta 更新）。

## 任务 R4 · 根目录右键菜单（与子目录同款，删除禁用）

**目标**：侧栏禁用浏览器原生右键；根目录弹与子目录相同的菜单，但"删除文件夹"灰显不可点。

**现状**：
- [SidebarTreeItem.vue:32-40](../../src/components/SidebarTreeItem.vue#L32-L40) `onContextmenu`：`isRoot` 时直接 `return`（不 preventDefault → 原生菜单）。子目录才 `preventDefault` + 弹菜单（当前仅"删除文件夹"）。
- 菜单 store：[contextMenu.js](../../src/stores/contextMenu.js)，菜单项无 `disabled` 概念。

**改法**：
1. **contextMenu store + [ContextMenu.vue](../../src/components/ContextMenu.vue)** 支持菜单项 `disabled` 字段：渲染时灰显（`pointer-events:none` + 灰色）、不响应点击。
2. **SidebarTreeItem `onContextmenu`**：去掉 `isRoot` 的早 return；根目录也 `preventDefault` + 弹**同一菜单**，但传 `disabled: true` 给"删除文件夹"项。（删除仍用 `handleDeleteFolder`，只是根的该项禁用。）

**边界**：根目录禁用项的 hover/点击无任何效果；子目录菜单行为不变。

**验收**：根目录右键弹自定义菜单、无原生菜单、"删除"灰显不可点；子目录右键正常可删；主观观感用户验。

## 任务 R6 · 收藏（md5 标签）+ 卡片爱心

**目标**：md5 为 key 的收藏集合；卡片左上角爱心（已收藏常显实心、未收藏 hover 显空心、点击或按 `L` 切换）。

**现状**：
- 无收藏相关代码。SmartFile 有 `md5`（视窗触发后算出并随快照持久化）。PhotoCard = [PhotoCard.vue](../../src/components/PhotoCard.vue)。
- 项目用 idb-keyval 做 KV（如 handleStore）。

**改法**：
1. **新建 favorites store**（`stores/favorites.js`，setup 风格）：内存 `Set<md5>` + idb-keyval 持久化（key 自定，如 `'favorites'`）；`isFavorite(md5)`、`toggle(md5)`、启动 `load()`。
2. **PhotoCard 左上角爱心**：
   - `favorited = isFavorite(file.md5)`（md5 未算出时按未收藏处理）。
   - 已收藏 → 实心 `fa-heart`，opacity 常驻 1。
   - 未收藏 → 空心 `fa-heart`（regular），opacity 0，`.photo-card:hover` 时 opacity 1。
   - `@click.stop="toggle(file.md5)"`（阻止冒泡开 modal），命中区给够。
3. **快捷键 `L`**：
   - modal 打开时：切当前 `modal.currentFile`（在 [useModal.js:226-269](../../src/composables/useModal.js#L226-L269) 的 onKeydown 加 `case 'l'/'L'`，注意 modal 有无 hover/input 守卫）。
   - hover 卡片时：切被 hover 的卡片文件。需一个"当前 hover 的 file"状态（Gallery/PhotoCard 维护一个 hoveredFile ref，mouseenter 设、mouseleave 清）；`L` 命中时切它。作用域：仅 modal 打开或有卡片 hover 时生效；输入框聚焦时不触发。

**边界**：md5 未算（未进过视窗）的卡片爱心不显示（点击/hover 时若 md5 仍空，可忽略或先触发生成——取忽略，简单）；GIF/SVG 无 md5 不参与收藏。

**验收**：点爱心/按 L 切换并持久化（刷新仍在）；未收藏无 hover 不显示爱心；客观可测 favorites store 的 toggle/isFavorite + 持久化。

## 任务 R11 · 视频总时长（md5 同 pass 抽取 + 卡片显示）

**目标**：视频进视窗生成缩略图/算 md5 时，顺带抽 duration，存 `_meta.duration`（持久化），卡片显示。

**现状**：
- md5 + 缩略图在视窗触发，入口 [thumbnail.js:33-77](../../src/services/thumbnail.js#L33-L77) `generateThumbnail`（视频走 `getThumbnailStrategy('video')`）。`_meta`（size/lastModified）随快照持久化；duration 字段目前无。
- [SmartFile.js](../../src/models/SmartFile.js) `_meta` 是 size/lastModified；fileToSnapshot/fileFromSnapshot 序列化 `_meta`（执行时确认字段透传）。

**改法**：
1. **duration 抽取**（纯函数，放合适位置如 `models/SmartFile` 或 thumbnail-strategies）：建临时 `<video>`、`src=blobUrl`、等 `loadedmetadata` 读 `duration`；超时/失败返回 null。**仅对视频**。
2. **触发点**：在视频缩略图生成的 pass 里（`generateThumbnail` 视频分支，或 video strategy 内），`_meta.duration` 未写时抽一次写入。注意只在视窗触发的懒路径做，不在扫描期做。
3. **持久化透传**：确认 `fileToSnapshot`/`fileFromSnapshot` 把 `_meta.duration` 带上（若 `_meta` 整体透传则自动；否则补字段）。
4. **卡片显示**：[PhotoCard.vue](../../src/components/PhotoCard.vue) 视频角标处加时长文本，格式 `M:SS`（≥1h 用 `H:MM:SS`）。`_meta.duration` 有才显示。

**边界**：损坏/无法解析视频 duration=null → 卡片不显示、不报错；非视频不抽；已写过 duration 不重复抽。

**验收**：视频卡片显示时长；刷新后仍在（持久化）；损坏视频不崩。客观可测 duration 抽取函数（mock video metadata）。
